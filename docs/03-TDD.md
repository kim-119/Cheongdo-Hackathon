# 03. TDD — 테스트 설계

원칙: **보안 경로는 테스트 먼저**. `packages/pii` 와 `egressGuard` 는 테스트 없이 머지 불가.

## 1. 단위 (Vitest)
| 대상 | 케이스 | 기대 |
|---|---|---|
| `detectRegex` | `010-1234-5678`, `01012345678`, `010 1234 5678` | 전화 3건 |
| | `900101-1234567` | 주민번호 |
| | `경북 청도군 화양읍 ○○로 12` | 주소 |
| | `농협 351-1234-5678-91` | 계좌 |
| | `12가3456` | 차량번호 |
| | 날짜 `2026-11-05`, 금액 `1,234,000원` | **탐지 안 함** (오탐 방지) |
| `mask` | 같은 값 2회 등장 | 같은 토큰 `[이름_1]` 재사용 |
| `unmask` | 토큰 → 원문 | 왕복 후 원문과 동일 |
| `unmask` | 결과에 없는 토큰 | 무시, 에러 없음 |
| `egressGuard` | 미가림 전화번호 포함 | `block` |
| | 토큰만 포함 | `pass` |
| `mergeEntities` | 정규식·LLM 범위 겹침 | 긴 범위 하나로 |

## 2. 통합
| 시나리오 | 방법 | 기대 |
|---|---|---|
| LocalAgent JSON 파싱 | LM Studio mock 서버 | 깨진 JSON → 재시도 1회 → 실패 시 정규식 결과만 |
| LM Studio 다운 | mock 503 | 정규식만으로 진행 + UI 경고 |
| 클라우드 전송 내용 | 클라우드 provider를 가짜 서버로 교체, 수신 본문 캡처 | 원문 PII 0건 |
| 매핑표 TTL | 10분 경과 | `/run` 410 |
| `add_todo` 툴 | 할 일 추출 작업 | DB에 n건 저장 |

## 3. 평가 (`pnpm eval`)
- `eval/cases/*.json` 가상 민원 30건 + 정답 엔티티
- 측정: 재현율, 정밀도, 처리 시간(p50/p95), 유출 건수
- CI 게이트: 재현율 ≥ 95%, 유출 = 0
- 결과 표를 README에 자동 반영 → AI 심사용 근거

## 4. E2E (Playwright)
1. 원문 붙여넣기 → 하이라이트 표시
2. "답변 초안" → 전송 미리보기에 원문 이름 없음 확인 → 승인
3. 결과에 원문 이름 복원 확인
4. 할 일 보드에 항목 추가 확인
5. 모바일 뷰포트(390×844) 동일 시나리오
