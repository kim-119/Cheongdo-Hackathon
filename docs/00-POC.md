# 00. PoC 검증 기획서 — 가림AI

## 1. 주제 선정 근거
| 기준 | 판단 |
|---|---|
| 참고 과제 | 기타 › **행정기관 AI 활용 시 개인정보·비공개 정보 안전 처리** |
| 경쟁 | 관광·농업·노인돌봄에 팀이 몰림 → 이 주제는 거의 비어 있음 |
| 개발 시간 | 텍스트 입출력만. 지도·센서·외부 데이터 수집 없음 → 짧음 |
| 기술 적합 | LM Studio(로컬) + 공용 API 하이브리드가 **곧 해법** |
| 생산성 | 민원 답변·공문·요약·할 일 추출 = 공무원 개인 생산성 |

## 2. 문제
- 청도군 공무원이 생성형 AI를 쓰고 싶어도 민원 원문에 이름·전화·주민번호·주소가 섞여 있어 못 쓰거나, 그대로 붙여넣는다.
- 결과: 생산성 손실 **또는** 개인정보 유출 위험.

## 3. 가설
| # | 가설 | 성공 기준 |
|---|---|---|
| H1 | 소형 로컬 LLM + 정규식으로 PII를 충분히 잡는다 | 테스트셋 재현율 ≥ 95% |
| H2 | 가린 텍스트로도 공용 LLM 결과 품질이 유지된다 | 원문 대비 품질 평가 ≥ 4/5 |
| H3 | 외부로 원문 PII가 한 건도 나가지 않는다 | 감사 로그 유출 0건 |
| H4 | 체감 속도가 쓸 만하다 | 1건 처리 ≤ 10초 |
| H5 | 업무 시간이 준다 | 민원 답변 초안 작성 시간 50%↓ (시연) |

## 4. 범위
- **IN**: 붙여넣기 → 마스킹 → AI 작업(답변 초안/요약/공문/할 일) → 복원 → 할 일 보드, 감사 로그
- **OUT**: 로그인/SSO, 파일(HWP) 파싱, 다중 사용자, 결재 연동

## 5. 검증 방법
- 가상 민원 30건(직접 생성, 실데이터 사용 안 함) → H1~H4 자동 측정 (`pnpm eval`)
- 시연 영상에 "전송 기록" 화면 노출로 H3 증명

## 6. 제출 전략 (AI 심사 7명, 최대 2회, 2차가 최종)
| 회차 | 목표 |
|---|---|
| 1차 | 핵심 흐름(마스킹→AI→복원)만 동작 + 측정 수치. **심사 피드백 수집용** |
| 2차 | 피드백 반영, 할 일 보드·감사 로그·모바일(Capacitor)·Azure URL 완성 |

AI 심사 대응: README 첫 화면에 **문제 / 해법 / 수치 / 배포 URL / 아키텍처 그림**을 한 장으로. 수치는 표로.

## 7. 리스크
| 리스크 | 대응 |
|---|---|
| Azure GPU 쿼터 없음 | CPU VM + 4B Q4 모델, 정규식 우선 |
